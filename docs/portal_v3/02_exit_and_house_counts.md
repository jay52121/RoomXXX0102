# 02｜从子房间出来，以及全屋人数账本

## 一、不要把“重新检测到人”当成“已经回客厅”

厨房、书房等正面门内的人可能一直可见；YOLO 出现与否不决定房间位置。两个门并排或成 90° 时，第一张检测框可能同时覆盖多个门，直接按框中心选门会制造错误来源。

新版用同一套有限门底边和人体身份账本处理进出，但证据路径不强求完全对称。进入常是证据减少；出来常是证据增加。

## 二、原来就在门后可见：直接检测地面反向跨越

对象已确认在子房间，继续被检测到时不增加新对象。只有其可信地面点从该门目标侧跨有限门线段进入完整客厅多边形，并在客厅侧持续得到不同时刻的确认，才提交：

`子房间 ID → 门 ID → 客厅 ID`

这不是“出现在客厅多边形的某个身体像素”。完整客厅多边形只与地面位置比较。人的头早已位于多边形外、手伸到门外，都不是穿门依据。

刚跨一步又立即退回时，取消尚未完成的候选。已经确认出来再进回去则是两个真实事件，而非为了不抖动永久吞掉往返。

## 三、第一次被 YOLO 捕获时已经快出来了：有界回看

源画面在 YOLO 处理前保留一个有限灰度帧环形缓冲。新候选人体在可靠锁定后，从当前人体区域选取具有归属约束的特征，沿过去最多约 900ms、至多 7 个已采样帧进行反向 LK 追踪。

此过程不是在过去画面里任意寻找“像人的运动”，而是回答：**当前已知人体上的这些局部纹理，之前在哪里？**

反向证据必须：
- 在多个空间格子上成立；
- 通过前后向误差检查；
- 过去多个时刻集中在同一个门框窗口；
- 运动在图像上有从该门向客厅侧展开的支持；
- 不是邻门同样可以解释，也不是视频间断、镜头移动或多人重叠；
- 当前首次可靠地面位置仍在该有限门槛附近，而不是已经走到客厅中央。

这个回看结果只提供“来源门”支持，不能冒充曾经测量到的脚点。随后仍要求人体准入和客厅侧地面持续确认。无法区分并排门、直角门时不强行扣掉任何一间房的人数。

## 四、短时遮挡重新出现，与真实房间出口必须区分

新外部 trackId 不等于新真人。已有客厅对象被家具遮住后，可能被 SimpleTracker 或远端跟踪器赋予新 ID。

新版额外维护独立于外部 trackId 的人数对象：
- 近位置、合理尺度、时间间隔受限、只有一个明确匹配时，恢复原客厅对象，不加人。
- 有可靠来源门证据的新检测，不能被客厅静止旧框随便“吸走”。
- 同一外部 ID 突然大幅跳位或两个人重叠时，冻结该对象迁移。
- 新检测可能是一个已失踪客厅对象，又可能是新进屋的人时，保留身份疑问，不重复加人。

此处不是通用人脸识别或跨房间身份识别。不同人在不可见房间里交换位置，单台客厅相机无法确定“具体是哪位”。对房间人数，恢复一个该房间的匿名占用名额已经足够；输出不假称这是生物身份验证。

当身份关联在本地与远端之间切换时，不清空已经确认的房间人数。旧检测 ID 解除绑定，保留匿名占用名额，再由新的可靠观测重新接续；不能因为服务器回退，把整个住宅突然归零。已有名额自身位置不明时，不随便新增一个可能重复的人。

## 五、人数不是每帧检测框数量

核心账本每个已接纳对象只占一个位置，位置可以是：
- 客厅；
- 某个子房间；
- 客厅盲区；
- 住宅外部（沿入户门离开后不计入屋内总人数）；
- 未确定位置。

房间人数从这些对象的位置直接汇总，而不是在不同回调中反复 `++/--`。迁移事件以对象、门、方向、事件阶段去重。室内 A→客厅→B 的迁移在全屋范围内守恒；没有中间可见证据时不伪造 A→B 的完整轨迹。

入户与盲区沿用现有标记。入户记录在内部用于“屋外”位置，**不应把它当作又一间卧室累加全屋人数**。客厅盲区属于屋内，但不与当前可见客厅人数混为一谈。

## 六、初始条件：不设置时绝不能把隐藏房间的零当成真值

如果视频开始时已有两人在主卧、三人在厨房，但从未出现在客厅摄像头中，仅凭客厅视频无法知道这五个人存在。这个问题与采用神经网络、光流、更多点、更多阈值都无关。

本版提供“**V3 起始人数（可选）**”设置：
- 设置各个房间和盲区在视频开始前的已知人数；
- 可选择针对当前测试视频，或针对当前摄像头会话；
- 以场景几何和视频 URI 隔离，不修改 `.Room` 文件格式；
- 保存后从视频开头重播。不能把播放中途的当前人数误填成视频初值；
- 清除初值后进入“初始人数未知”模式。

视频仅在开头 500ms 内启动新算法会话时应用已保存初值。直接从中途开始或倒退到中途，会显示初值未知，不把时间零点的人数冒充此刻人数。

起始人数被建立为匿名占用名额。之后在该房间首次检测到或确认出来的人，接续已有名额，而不是在原始人数之上再多算一人。

**未知模式下的显示是“已知人数”，不是全屋完整真值。** 屏幕会明确写出“隐藏初值未知”；已知对象自身还有门或身份歧义时，同时显示位置候选与人数区间。初始未观测人口并没有可由视频确定的有限上界。

为兼容现有房间 UI，`persistentPersonCount` 仍接收整数，但这是 V3 当前提交值；是否初值已知、是否存在待定项，应以新增 V3 叠加面板和调试字段一起解释。

## 七、延迟确认与人数区间

例如已知一个人在客厅门口消失，A、B 都有一定可能：

`提交位置：客厅；候选：客厅 / A / B`

此时不能对 A 或 B 执行整数增减。提交值保持不动，界面显示可能范围。后续重新出现在客厅且身份连续可恢复，就撤销门候选；后续明确来源门，可以完成有证据的恢复。新版不通过“过了 N 秒必须选一个门”结束歧义。

“提交值不动”不代表声称他此刻一定仍在客厅。必须同时看待定标记。错误地强制给每间房一个看似精确的数字，比明确不确定更危险。

## 八、学习什么、不学习什么

本版只从**可靠地面实测跨越**中记录每扇门的进、出图像运动方向，分别保留有界样本，经持久化按场景隔离。达到最低样本数后，它只作为相邻门比较中一个很小的方向先验。

它不替代门底边相交，不把模糊门事件作为训练真值，不根据“后来有人出来”无条件倒推此前必定是同一个人，不声称几次即可学出可靠三维方向或完整遮挡曲线。

完整“每扇门进入/退出可见性分布学习”尚未实现。本次已实现的是保守、不会自我强化错误的方向先验；这一区别在日志与代码中一致。

## 九、边界与测试

测试包括：屋内持续可见不等于出来、测得反向跨门、退出复用原房间名额、家具遮挡后新 ID 恢复、相邻门共同端点保留歧义、初值接续、室内迁移守恒及异常时间序列。

如果一个出口从始至终被另一个人或家具遮住、当前人体回看也无法唯一匹配某个门，则来源应为待定。更多相同机位的模糊样本不能自动消除不可观测性。改善机位、补充明确的门口示例或额外传感器属于之后的产品选项，不在本版里冒充已解决。
