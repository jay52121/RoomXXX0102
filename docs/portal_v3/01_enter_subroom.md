# 01｜进入子房间：门底边优先，人体光流补充

**实现版本：Portal V3 · 门线与人体光流（实验）。** 本文与同目录另外三份文档共同定义本次实现；不是已验证的准确率承诺。旧 Legacy、ViT、MIL 版本仍可在设置中选择，新版独立产生房间事件与持久人数，不借用 Legacy 的判定结果。

## 一、先纠正空间解释

依据用户提供的《roomxxxmp4 空间标定数据与语义说明》及随后澄清：只有客厅被完整标定；其他“房间”记录表达通往该房间的门口及图像窗口，不是该房间的完整地面范围。门后人仍然可见，也不等于仍在客厅。

文档曾将非主空间四边形称为“Portal 过渡区”。**它可以用于图像归属筛选，但不能据此把四边形上边解释成门后的某个物理深度。** 门框是近似竖直平面，人的足底是在地面上；任意躯干像素都不能直接拿来跨地面门槛。把门框变换成矩形是二维图像变换，不会恢复人体三维位置，更不能证明“v 增长即深入房间”。本实现不使用这项错误假设。

源码 `MainActivity.buildPresenceDoorSnapshots` 按客厅 **起始顶点 id** 查找 `occupiedWallIds`，取该顶点到下一个顶点作为门底边。上传说明正文写的是 `edgeIdToNext`，但上传的 JSON 对应的是起始顶点 id；例如主卧绑定 17，实际是顶点 17→1，对应的 `edgeIdToNext` 是 30。本版保留真实工程约定，不批量改写配置。

对每扇门只需要以下数据：
- 关联目标空间的稳定 ID；入户、盲区的原有标记。
- 客厅侧有限门底边，以及通过客厅多边形局部内外测试得到的方向。
- 可选的门框图像多边形：用于人体可见部分的归属证据，不作为房间地面。
- 按图像宽高比校正后的距离。不是“米”，也不从画面左右强推真实三维朝向。

## 二、唯一目标与证据职责

目标是：对已经通过人体准入的对象，确定“客厅→哪扇门→哪个子空间”，只在证据充分时改变其账本位置。

| 证据 | 可以支持什么 | 不能证明什么 |
|---|---|---|
| 高置信、解剖位置合理的双脚 | 人的地面位置、有限门底边的跨越 | 检测器置信度不是绝对真值 |
| 经完整人体历史校验的框底 | 双脚缺失时的次级地面观测 | 半身框或变高框的底部不是脚 |
| 同一个人的短时光流 | 遮挡前后局部视觉连续性、短时位移、门框归属 | 任意身体点“过线”不是足底过门 |
| 跟踪失败 | 某个局部纹理已无法可靠匹配 | 不等于该人体被墙遮挡，更不等于进入房间 |
| 人体原位置恢复已建立的背景 | 该位置的前景确实离开或被替代的附加证据 | 单独不能区分进门与家具遮挡 |
| YOLO 无输出 | 当前成功处理的范围没有合格检测 | 不等于无人，也不等于房间切换 |

ViT/MIL 框不进入新版事件判定。YOLO 框仍用于人体区域限制、身份关联和受严格约束的框底观测，不再把“大框是否漂亮”当任务。

## 三、视觉机制：有空间覆盖、有质量上限，而不是盲目增加点数

`PortalV3Vision` 使用已有 OpenCV 核心模块的金字塔 LK 光流，前向跟踪后再反向核对。人体候选区域由可信躯干、四肢、头部生成，收缩躯干区域，排除其他人的框。**这是所有权近似约束，不是精确人体分割。**

人体框分成 4×8 个格子，每格最多 25 个有纹理的点，单人上限 800；全局最多 1800 点、最多 4 个活动点云。图像保持比例，长边最多 640。没有足够纹理时如实少取点，不把平坦衣服上随便撒的点伪装成可靠特征。每 300ms 至多补充一次；补点必须仍有已锁定且骨架可信的本人人体。检测不可靠后不在门框里重新找一批“新人体点”。

点数只是预算，不是可靠性指标。相邻点高度相关，终止证据按人体空间格子去重；同一格的几十个点不能得到几十票。门框重叠处不允许一个终止点给两扇门同时计票。点云的多数一致运动与离群过滤只能排除部分背景，不能保证所有点真属于人。

正反向误差、纹理匹配误差、区域有效性、运动离群和其他人遮挡共同控制存活。有效跟踪少于 3 个空间格子、存活率不足或位移不合理时，不提供可信位移。失去监督后最多保留短暂点云，不无限追墙。

## 四、主判定：看到足底跨门，进入后仍可见也立即确认

`FlowGroundEstimator` 不使用原始 `PoseResult.landingPoint` 的 0.00 脚踝阈值。脚踝置信度至少 0.60，位置必须在人体下部、低于胯部、靠近合理框底；画面或 ROI 底边截断时不将框底作为可靠落点。

双脚满足条件时为强观测；单脚只作弱支持。只有积累了完整人体参照，且身高、框高变化、下肢可见性等通过检查后，才启用校准框底。局部框突然缩短、夸张变高，或者脚点置信度差时，都不制造“新脚点”。

一次可见进入必须同时满足：
1. 本人已准入，最近有客厅侧的可靠地面历史。
2. 新可靠地面位置到了目标侧，轨迹与**有限门线段**相交，且已离开完整客厅多边形。不能只跨无限延长线。
3. 位移没有超出合理短时范围，身份与多人重叠没有冲突。
4. 相邻门并行竞争，分数没有足够差距时待定，不取“最近门”硬选。
5. 目标侧至少两次不同时刻观测，间隔达到确认要求；往返探身立即撤销未确认候选。
6. 事件只提交一次。进入后在门框内继续被 YOLO 检到，仍属于目标房间。

这个分支处理厨房、书房等正面门，也处理仍有可靠足底的侧门、部分透明情况。它**不等待完全消失**。

## 五、补充分支：左侧近门刚进入就消失

仅当真正观察到“接近门槛末端”的过程，才允许遮挡推断：
- 最近可靠地面点已非常靠近有限门线段，并存在真实地面接近趋势；
- 足底已进入很窄的门槛接触不确定带，或很短的可信光流延续使整个位置不确定区越过门线；
- 人体可见点云近期主要归属于同一门框，且与第二候选有明显差距；
- 已成熟人体点在该门框处丢失，同时其原位置有背景恢复支持；
- 终止证据来自多个格子和多个时刻；近门瞬间遮挡则要求更严格的接触和背景恢复条件；
- 不是视频跳帧、曝光突变、相机移动、推理失败、ROI 未覆盖或其他人挡住。

**“有序衰减”不是必要的自然定律。** 左侧门可以突然消失；光流也可能因模糊成片失效。代码分别处理多时刻衰减和严格门槛接触下的突然遮挡，但证据不足就保留待定，而不是为了覆盖所有案例降低门槛。

背景从未被可靠看见的地方不能提供背景恢复证明。这种情况可能漏掉本次遮挡进入；可见跨门仍可正常工作。这是明确的保守边界。

## 六、各类情况的结果

| 场景 | 新版行为 |
|---|---|
| 正面门，进屋后仍可见很久 | 可靠足底跨门后确认，继续跟踪且不重复计数 |
| 右侧远门，进后短暂可见再消失 | 优先足底跨门；后续消失不再重复提交 |
| 左侧近门，几乎立刻消失 | 门槛接触＋专属人体终止＋背景恢复；不足则待定 |
| 两扇并排门或直角门投影混淆 | 有限线段与完整客厅内外关系先过滤，再比较独立门证据 |
| 路过、停在门口、探身再回来 | 无可靠完成跨越，不改变人数 |
| 门框附近沙发挡住人体 | 不因画面上重叠门框就算进门，详见 03 |
| 玻璃、反射、门扇运动 | 有可靠足底可走主分支；透明性与反射消歧没有声称已解决 |
| 多人挤在同一入口 | 身份/点云重叠时冻结该对象的事件，不虚构精确归属 |
| 盲区 | 无门框几何则不走门框终止推断，只接受可靠底边跨越或保留不确定 |

## 七、地图需不需要增加标记

普通可区分场景可直接使用当前门底边＋门框窗口，不要求再标“左门/右门/正门”，也不自动声称知道门后可见深度。

但如果家具遮挡边与门口在相机投影中重合、所有足底观测都在接触前丢失，单目序列确实可能支持两种现实过程。算法必须待定；增加一小块人工排除区、一次门口引导示例或更好的机位才可能消除歧义。本版不自动创造缺失的三维信息，也不要求用户现在重画全屋。

## 八、实现位置与检验

核心：`PortalV3Core.evaluateMeasured/evaluateHidden`；视觉：`PortalV3Vision.advance/observe`；地面：`FlowGroundEstimator`；适配：`PortalV3RoomAlgorithm`。

默认参数是可运行的初始工程值，不是实测最优值。用户实际视频验证前不能承诺准确率。测试覆盖正面持续可见进入、相邻门、共同端点歧义、探身返回、半身框、门前掉检、错误光流投票等。

参考：上传空间标定说明；仓库 `MainActivity.buildPresenceDoorSnapshots`、`PoseData.kt`、`SimpleTrackerEngine.kt`；OpenCV 官方 `calcOpticalFlowPyrLK`、`goodFeaturesToTrack` API 文档。
