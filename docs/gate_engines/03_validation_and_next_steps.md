# 三版都不理想时：按失败原因处理，不再换名词

## 如何判输赢

以前讨论中的预测分数不是实测准确率，不能作为验收标准。三版共享地面估计、门底边和账本；差分与 MOG2 都依赖可信背景，光流版又复用部分背景证据，所以它们不是三个统计独立的裁判。不要用三票多数表决自动认为正确。

先用同一视频、相同地图、相同起始人数、相同人体检测配置，从开头分别播放。至少覆盖：正面门进入后仍可见、近侧门快速消失、远侧门渐隐、相邻门、门前经过不进入、探身折返、家具遮挡、静止人体、空沙发误检、出门新 ID、多人交叉。

看错门、漏进/漏出、误报、最长人数错误时间和实际输出帧率，不只看最后一帧人数。初值未知的情况单独统计；待定不是正确整数，也不应被藏进“准确率”。

本次会运行纯逻辑回归和 Android 构建。它们能检查规则与工程可编译性，不能证明目标手机帧率、实际像素跟踪质量或用户视频的识别准确率。没有真机数据就不填写 20fps 或 95% 的实测结论。

## 调整顺序

第一轮只使用默认配置。第二轮按症状只改一组：视觉分辨率/噪声参数，或跨门确认/地面可信度，或光流窗口/点数。出现一次明显错门或家具遮挡误报后，优先处理误报，不为了提高表面召回率无限放宽“到达门槛”的要求。

每次保存后从头重播。只重建背景可保留当前人数，但比较不同参数时仍建议同一初值重新开始。保存导致地图、来源或参数实例重置，是测试边界，不是实际进出事件。

## 调参后仍失败，下一步依证据选择

### 1. 三版都错在地图或脚点

先修共用输入契约，而不是增加第四个跟踪器。检查真实视频截图上门底边位置、裁剪/缩放/旋转一致性、脚点置信度，以及原始坐标的边关联。相邻门共端点附近明确保留歧义。

若问题是脚点被家具截断，可增加一个小范围的人工“遮挡边界或可信接触带”标记，或者从几次明确标好进出与门前经过的示例中校准该门的观测关系；不需要补画整个子房间，也不能把门框上沿当作门后深度。样本必须有独立标签，不能由当前算法自己的猜测自我训练。

### 2. 主要错在人体与背景分不开

下一项有价值的升级是门口局部的人体分割，而不是全屋稠密光流。只在有真人候选的门口调用轻量分割模型，实测其目标手机耗时和半身召回，再接入现有门底边/账本。分割仍有遮挡、暗衣和漏检风险，不能承诺换模型就解决。

### 3. 主要错在门口快动作没有采到

先看完整轮次。如果 Pose 50ms、截图和视觉又用了 20–40ms，串行输出约 11–14fps 是可能的，不是设置 20 就能得到 20。先降低读回分辨率、减少不必要 UI/日志开销，确认 GPU 后端与持续温度；需要时再改为带实际帧呈现时间的解码采样或独立有界视觉测量通道。

独立通道必须有明确的帧所有权、时间水位和迟到观测策略，不能把“最新光流”和“旧 Pose”拼成同一帧。当前这次交付未假称实现该异步融合层。

### 4. 主要错在多人并行、交叉或新 ID

先保留原始进出轨迹和身份冲突样本，改善身份关联/外观接续及门口实例分离。新的检测 ID 不等于新住户；房间里匿名名额的接续可以满足计数，但不能声称已经识别人脸。一个人在客厅长时间消失、另一个人同时从门出来时，现有保守规则可能暂缓入账，需要针对这种失败修身份层，而不是调差分。

### 5. 特定门从这个机位根本没有可区分证据

在某个机位，走到家具背后与穿过门可能产生无法区分的图像序列。不能据此断言所有单目算法都没有价值，但也不能保证仅增加点数、改变阈值或“学习几次”就恢复未被拍到的信息。

此时优先小幅调整摄像头或门口可见区域；仍不够再考虑第二视角或门口专用传感器。普通门磁只检测门开关，本身不能独立计数或区分方向。是否增加硬件应由具体失败视频证明需要，而不是先把项目升级成大规模视觉研究。

## 可继续复用的东西

无论最后哪个视觉方案胜出，原始门标定、有限底边、严格时序、人体准入、匿名占用名额、事件去重、初始人数与诊断记录都继续使用。失败后应替换明确失败的那一层，不再把整个房间系统反复推倒。

## 本版仍需真机验证的项目

实际输出帧率及低分位、视频显示卡顿、截图和视觉耗时分布、连续运行温升、内存是否稳定、左右近远门召回、正面门内持续可见、静止人体、多人同门、门扇开关和灯光突变。成功编译和单元测试不是这些项目的替代品。
