# 参数和 APK 使用说明

## 入口

在「设置 → 房间算法」中选择「门口差分（高帧率）」「门口光流（精度优先）」或「OpenCV MOG2（自适应前景）」。不是选择原来的 Portal V3。

「门口算法参数 / 诊断」提供默认、保守、性能优先、自定义、重建背景和导出最近诊断。参数按三个稳定算法 ID 分别保存，切换参数会创建新算法实例；修改后从视频开头重播，避免把中途画面当成零点人数。起始人数复用现有 V3 设置，不修改 `.Room` 文件。

默认参数不是准确率证明。先分别使用默认配置看同一段失败视频；只有知道失败发生在哪一层之后才调整。不要一次改变五个阈值。

## 共用参数

| 参数 | 默认 / 可调范围 | 怎样使用 |
| --- | --- | --- |
| 采样上限 `sampleHz` | 20 / 5–30 | 是请求上限，不是保证的输出帧率。增大不能缩短一次推理本身。 |
| 截图长边 `captureEdge` | 1280 / 640–2560 | 截图慢时可试 960；远门细节不足可试 1600 或原画面长边。手部检测器存在时保留原截图分辨率，此项不强行降低手部输入。 |
| 视觉长边 `imageEdge` | 差分/MOG2 512，光流 640 / 256–960 | 门在图像中很窄时优先提高它，而不是盲目降低证据要求。性能不足可试 384。不是修改 YOLO 的 640 模型输入。 |
| 最大有效帧间隔 `frameGapMs` | 300ms / 100–600ms | 超过即断开短时视觉证据，不补算积压。不能靠放宽到很大数值掩盖实际卡顿。 |
| 差分阈值 `differenceThreshold` | 22 / 8–60 | 噪声、曝光引起大量假前景可增大；衣服和背景接近而看不到前景，可小步降低，例如 22→18。MOG2 的主前景灵敏度由方差阈值控制。 |
| 背景建立 `warmupMs` | 700ms / 300–4000ms | 要求门口空闲稳定且至少四次观测。初次就有人挡住门时，不应强行把人学成背景。 |
| 背景学习率 `backgroundRate` | 0.012 / 0.001–0.1 | 仅空闲且稳定时使用。光照缓慢变化可适度增大；不要试图靠高学习率让停在门口的人“消失”。 |
| 门接触带 `contactHeight` | 人体框高的 0.10 / 0.04–0.18 | 内部还有归一化图像高度 0.008–0.035 的限幅。门槛已正确但轻微定位误差时才小幅增大；家具在门前时放宽会增加误报。 |
| 直接跨门确认 `crossedHoldMs` | 120ms / 60–600ms | 抖动、探身误报时提高到 180–250；真实快速穿越漏报且地面轨迹正确时可以小幅降低。始终要求至少两个独立有效观测。 |
| 遮挡确认 `vanishedHoldMs` | 240ms / 120–800ms | 短时掉检误报可提高；降低会更快，也更容易把短遮挡当成进入。还要求至少三次背景恢复观测。 |
| 证据保留 `coastMs` | 1200ms / 500–2000ms | 右侧门遮挡较慢时可试 1600；不能延长为无限猜测。 |
| 人体覆盖格数 `minOwnedCells` | 4 / 3–12 | 防止只靠手、影子或一小块纹理。格数太少先检查分辨率和人体区域，不要直接降到最低。 |
| 背景恢复比例 `restoredFraction` | 0.88 / 0.75–0.98 | 误报时提高到 0.94；残留噪声导致迟迟不确认可小步降低。它同时要求整个门窗口剩余前景足够少，不只是旧人体位置空出来。 |
| 最少前景 `minForegroundPixels` | 10 / 4–80 | 在视觉缩放后的门裁剪中计数。增加去噪但会损失远小人体；MOG2 连通域清理也受它影响。 |
| 脚点置信度 `footConfidence` | 0.60 / 0.45–0.90 | 这是房间算法使用脚点的条件，不改 YOLO 检测阈值。低质量脚点乱跳应提高；不要为了捕捉最后半身而接受虚构脚点。 |
| 真人准入时长 `admissionMs` | 200ms / 120–1000ms | 始终叠加原 Tracker 锁定、可信骨架、至少三次地面观测和净运动；时间到了不自动收下静止假人。 |
| 视觉软预算 `workBudgetMs` | 24ms / 8–60ms | 超过时跳过后续非必要背景/补点工作。不是可中断原生调用的硬实时保证。 |

## 差分版：优先调整什么

前景太碎或没覆盖真人：先提高视觉长边，再尝试降低差分阈值。前景充满门口：先看灯光、门扇状态和背景是否干净，再提高差分阈值或重建背景。站住就误判：确认存在稳定背景并检查剩余前景比例；不应该只依赖帧差。

脚点已经连续跨过底边却没事件：检查跨门确认时长、有效帧间隔、人体是否准入，以及是不是跨了门线的延长线。此时调整差分阈值没有意义。

## 光流版：附加参数

| 参数 | 默认 / 范围 | 代价和用途 |
| --- | --- | --- |
| 每个人点数 `pointsPerPerson` | 192 / 48–320 | 只在门框内取点。默认全局上限还会约束总量。可试 256，但没有纹理时增加上限不会凭空产生可靠点。 |
| 全局点数 `maxPoints` | 384 / 96–640 | 多个门口同时活动时分配预算；多人遮挡仍保守，不因更多点就允许混合身份。 |
| 金字塔 `pyramidLevel` | 2 / 1–3 | `maxLevel=2` 包含 0、1、2 层。更大可处理更大位移，但更耗时，并不解决图像完全看不到的问题。 |
| 窗口 `lkWindow` | 21 / 奇数 11–31 | 大窗口可能更耐运动和模糊，也更容易混入门框背景；不是越大越好。 |
| 双向误差 `fbError` | 1.5 像素 / 0.5–3.0 | 单位是缩放后局部门图的像素。放宽可增加存活点，也会增加错误对应；漂到门框时应收紧而不是放宽。 |

只有确实存在少量可靠运动证据、且帧间隔正常时才考虑增加点数或窗口。全局预算不足导致 `BUDGET_OVERRUN_NO_BACKLOG`，先减少点数或图像长边，避免通过放宽时间间隔来硬接远帧。

光流版对遮挡确认额外要求运动方向与此前地面运动一致，因而可能比差分版更保守。它不会在无有效光流时悄悄退成另一种推断，以免测试时名实不符；可靠脚点的直接跨门路径仍可独立工作。

## MOG2 版：附加参数

| 参数 | 默认 / 范围 | 用法 |
| --- | --- | --- |
| 方差阈值 `mogVariance` | 16 / 8–64 | 噪声前景太多可试 20–24；暗衣服被吞掉可小步降低。 |
| 历史长度 `mogHistory` | 120 / 30–600 | 与背景学习有关；本版在事件期间冻结、空闲期使用显式学习率，因此它的作用受这些策略限制，不是首选调节项。 |

本版固定使用三种高斯成分，并排除 MOG2 的阴影标签。深色衣服也可能被阴影模型误判，所以“去阴影”并非无损。门长期开/关状态变化且无法重建空闲参考时，不应靠放宽确认阈值强行出结果；先在无人门口重建背景。

## 预设具体改动

默认：以上默认值。保守：直接确认 200ms、遮挡确认 400ms、恢复比例 0.94、最少覆盖六格。性能优先：视觉长边 384、单人 96 点、全局 192 点、LK 窗口 15、软预算 16ms；差分/MOG2 不使用其中的光流参数。

三个方案保存各自参数，恢复默认不会更改另外两版，也不改变原始人体检测阈值或 Tracker。

## 看什么诊断

画面显示当前算法、脚点、活动门口、前景或背景恢复格、光流尾迹、输出帧率、视频渲染计数、截图/人体推理/视觉/判定耗时、有效帧间隔和点数。差分与 MOG2 的光流点数应为零。

“忙跳过”仅计工作线程繁忙时拒绝的采样请求，不是解码器丢帧总数。“视频渲染”来自播放器调试计数，不是屏幕合成流畅度的完整测量；真机是否卡顿仍要结合画面观察。摄像头模式没有该播放器计数。

导出保留最近 1200 条诊断，包含参数、时间戳、各阶段耗时、每扇门的人体覆盖/剩余前景/背景恢复/运动校验及人数事件。`previous_round_ms` 是上一完整轮次耗时，避免把尚未结束的本轮耗时假装成最终值。

纯局部亮暗变化没有人体语义；前景标记只是调试测量，不是经过像素级分割验证的真实人体轮廓。更多格点也不是更高置信概率。
