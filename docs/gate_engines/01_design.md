# 三套门口算法：设计与实际实现

## 先确定什么是门，什么是房间

当前 `.Room` 中只有客厅是完整标定的可见空间。子房间的四边形是摄像头画面上的门口窗口，不是子房间完整地板，也不是经过三维标定的纵深平面。门底边继续复用工程现有解析，不能把 `occupiedWallIds` 按文字说明误解释成另一套边编号。

门框互不重叠，让一个图像位置的门框归属更明确，但不意味着“整个人只能同时覆盖一扇门”，也不意味着“在门框内消失必定进门”。人在门前横着走、蹲下、被家具遮住、灯光改变，都可能产生相似像素变化。因此三版都不使用门框上方位置作为真实房间深度，也不以差分质心向上作为穿门证明。

## APK 的三个新选项

| 设置名称 | 稳定标识 | 实际视觉实现 |
| --- | --- | --- |
| 门口差分（高帧率） | `gate_diff` | 门口帧差、冻结背景差、人体归属区域与背景恢复，完全不调用光流 |
| 门口光流（精度优先） | `gate_flow` | 在门口差分基础上增加局部正反向 LK、空间配额与运动一致性校验 |
| OpenCV MOG2（自适应前景） | `gate_mog2` | OpenCV 高斯混合背景模型、阴影标签过滤、连通区域清理，完全不调用光流 |

三版都真正输出门事件及房间人数，不是只画框，也不是复用 Legacy 人数的展示壳。为了能定位差异，共用同一份可靠地面观测、有限门底边、身份接续与人数账本代码。旧 Legacy、V2、V3 保留，默认旧选择不变。

第三版使用成熟开源视觉组件，不等于整个家庭人数算法已经在各种家庭中得到验证。光流版的“精度优先”表示增加校验和图像细节预算，不承诺一定比其他两版更准；强校验也可能增加漏报。

## 三版共同的直接跨门路径

1. 复用当前 SimpleTracker / RemoteByteTrack 的人体锁定结果，再检查连续可信骨架、可靠地面观测及净运动。沙发偶发误检不因为持续时间长就自动转成真人。
2. 两个可信脚踝构成地面观测；只有历史完整人体高度、下肢可见和框高稳定同时满足，才允许框底替补。单脚、被 ROI 截断的下边缘、突然缩短的半身框不形成强跨门证据。
3. 前后地面点必须穿过该扇门的有限底边，而不是它的无限延长线；两侧必须超出位置不确定带。
4. 目标侧在不同有效时刻重复确认，默认至少两次且持续 120ms。短暂探身折返取消尚未提交的迁移。
5. 进入正面厨房、书房后仍然可见，不影响已经确认的房间归属。出来时以反向地面跨越确认，不以“YOLO 又检测到了”确认。

门框图像只给人体视觉测量限定范围；客厅多边形只与地面位置比较，不与头、肩、衣服像素比较。

## 遮挡进入：视觉是补充，不是通行证

只有已确认真人此前有可信地面轨迹，并且地面支撑到达门底边附近，才允许建立门接触候选。人体可信骨架附近的区域与门框前景相交，形成该人的局部所有权；不对客厅中央的人建立光流。

检测消失后不再扩张所有权。使用曾经确认的人体区域检查背景是否恢复，并同时检查整个门窗口是否仍存在显著前景。后一项用于避免把人体平移后留下的空白，当成人已经彻底消失。

遮挡迁移必须同时满足：近期地面运动明确朝门底边、最后地面点接近门槛不确定带、唯一候选门、足够多的空间格曾被该人覆盖、有效背景已经建立、连续背景恢复、检测确实覆盖原位置并成功返回无人。光流版还要求门口人体纹理的运动方向得到正反向校验，且与此前地面运动一致。光流位移不冒充脚点。

门前横向经过、身体影子、门扇运动、光流失效、推理异常、画面中断均不能单独触发迁移。身体仍在门口静止时，帧差可能为零，但稳定背景差通常仍保留前景，故不能按“无运动”判进入。

极近侧门如果连最后可信地面点都远离门底边，或家具就在门前形成无法区分的遮挡，这三版会保留待定，不能靠扩大阈值假装解决。详见后续处理文档。

## 出门和新身份

已有房间对象在门后可见，沿反方向穿门，直接迁移到客厅。新人体第一帧已经在客厅侧时，可使用“门内前景先出现、随后该门附近出现可信人体”的短期来源提示，但仍要求唯一门、人体锁定、地面接近门槛和客厅侧持续确认。门内先动不等于新人口。

同一时间并排门、共同端点、多人身体覆盖导致来源不唯一时，保留歧义。已有房间匿名名额优先接续，不重复增加全屋人数。客厅家具遮挡后产生新检测 ID，只有时空位置和尺度匹配唯一时才重绑定；不能证明是新人的情况不重复入账。

这不是跨房间的人脸识别。它保存的是人数对象或匿名占用名额，不声称辨别不可见房间中谁换成了谁。

## 三版视觉区别与资源边界

### 差分

门口窗口保存上一张图和空闲时建立的参考背景。相关人体出现后冻结背景。帧差用于检查运动及稳定性，参考背景差用于保留静止前景。所有归属都裁剪在原始门框内部，边界像素适度置中立，不通过膨胀让相邻门重新发生归属重叠。

### 光流

只从门框内已确认的人体区域取点。默认单人 192 点、全局 384 点，视觉长边 640，21×21 窗口，`maxLevel=2`（含第 0 层共最多三层），前后向校验。一次补点只运行一次角点检测，再分配空间格配额，不再逐格反复运行角点检测。失去可信人体监督后不补点；时间间隔过大时终止测量，不把失败当成进入。

### MOG2

使用现有官方 OpenCV 4.13 的 `video` 模块，不增加 contrib 依赖或额外神经网络。阴影默认标签 127 不作为前景，保留 255 前景；连通区域过滤极小噪声。背景只在无相关人体、无活动所有权、画面稳定时学习，事件期间学习率为零。持续的大幅门扇状态改变可能需要在空闲时重建背景，而不是把门扇运动认成人。

## 调度和时序

新三版不启用 V3 的 32 帧灰度缓存，不调用 `through()` 补算积压。回放在截图前原子检查工作线程是否空闲；空闲才获取当前画面，提交一个串行任务。任务完成后按目标采样周期继续获取最新画面。没有历史追赶队列，也没有把不同人物状态机并行写入账本。

默认采样上限 20Hz。截图默认长边 1280；YOLO 模型输入仍由原分析器处理为 640，视觉支路再缩至 512（光流 640）。手部检测器存在时保留原截图分辨率，避免改变已有手部链。灰度与视觉计算位于推理工作线程，不再在 UI 定时器逐像素转灰度。

当前是有界、同帧串行的实现，不是假称已经做成独立 20Hz 视觉线程。默认空闲门背景扫描约 5Hz；接近门时按有效推理帧更新。摄像头路径继续沿用现有 CameraX 单帧回调，不凭空改变其采样器。

20Hz 是请求上限，不是实际帧率保证。若 Pose 本身恰好耗时 50ms，串行链还需要截图、视觉、状态机与绘制，输出必然低于理论 20fps。10fps 需要大多数完整轮次低于 100ms。软预算能停止后续补点或背景任务，不能中断正在执行的一次原生 OpenCV 调用。

## 人数、初值与边界

三版共用已有的起始人数设置；每种算法自身的参数与运行状态隔离。视频开头 500ms 内才应用视频零点初值；中途启动显示隐藏初值未知。室内迁移移动一个名额，不反复加减；入户门连接屋外，屋外名额不计全屋人数；盲区属于屋内，但没有门框时不运行图像消失推断。

切换算法、改变参数或换视频后应从头重播。只重建背景不会清空人数。身份跟踪后端变化保留已确认占用名额。隐藏初值未知或来源待定时，不把提交整数包装成无误差的全屋真值。

未新增玻璃反射专用处理、像素级人体分割、完整门可见性学习、无限长遮挡身份恢复或真实三维重建。
