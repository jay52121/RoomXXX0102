# V5.3 局部穿门状态判定——第四次实测后的结构性改造

## 改造依据

最新 V5.2 Android 录制：1737 个分析帧、1247 条局部差分信号、32 条人工事件。按门、方向、一对一实际**输出帧视频时间** [-100,+1000]ms，V5.2 只有 16/32，另有 8 条未匹配输出，500ms 内 12/32。人体框提前重叠策略让 32/32 人工事件在标注时刻前已开始观察，问题主要位于判定而不是全门采集。

## 设计

1. 采集延续 V5.2 的人体框和门区重叠启动，不让所有门持续 20fps 做重型差分，仍然最多同时处理两扇门。
2. 每扇门保留早期观察，但 V5.3 只把最近 1150ms 内的 ACTIVE 运动用于实时候选；时间起点不再是早期 ARMED / ACTIVE 开始。
3. 候选成立必须再检验最近180ms与240–640ms前的**新变化**：人体侧向位移、前景覆盖率或图像门区空间分布是否一致。走向门内、遮挡后消失和真实跨门不再直接画等号。
4. V5.3 直接使用门区已计算的 8(相对深度)×4(门线方向) 分布网格，以二维伪深度上的相对占用前沿作为佐证；**不是三维测距**，单独网格变化不能凭空确认穿门。
5. 同一追踪目标跨不同门只在220ms内视为可能竞争，取消此前固定950ms的强制互斥，以免连续 EXIT 后 ENTER 被拒绝。人数账本的其余防误报逻辑保留。
6. V5.3 事件的 timeMs 取实际对外发表所在分析帧的视频时刻；不得用历史识别帧回填来满足时限。

## 当前回放的边界

V5.3 Python 条件镜像在最新完整差分输入上的初步诊断约26/32、1条未匹配输出，500ms内约20条。这是阶段性算法原型而非 Android 完整像素回放，也未实现全部32条达标。Kotlin 回放固定使用4份来自**同一段原始视频**的不同采样，分别报告严格匹配、误报与延迟；测试阈值并未谎称全对。

V5.3 真机测试还需验证提前获取的网格分布、丢帧、相邻门竞争、多人体和门口折返。已知存在漏报与泛化风险，不作为默认算法。旧 V4/V5.0/V5.1/V5.2 并列保留，出现退步可立即切回。

## 实测动作

从 `9月新房间判定算法` 工作分支正常编译安装，在房间算法中选 `V5.3 · 局部穿门状态识别（验证版）`。播放整段视频并导出全程判定；按每个事件**实际输出所在帧**与 T 做 [-100,+1000]ms 匹配，另外检查 +500ms、误报与最终人数。若仍失败，保留本次完整 JSON 及其 8×4 空间网格作下一轮分析。
