# Portal V4：三个可切换方案与使用说明

## 目的与结论边界

本次是在同一 APK 中实现三种真实视觉测量后端，共用相同的可靠地面位置、有限门底边判定、人体准入和人数账本，方便比较。不是给同一算法换三个名称，也不是再让 V3 对积压图像逐帧追赶。

此前讨论中的“92 分、93 分、95% 准确率上限”等没有测试数据支撑，不能用作验收标准。B 的“精度候选”表示提供更多运动证据，不表示已经实测胜过 A/C。当前没有用户实际视频或目标手机的测量，不能承诺 10/20fps 或某个准确率。

## 设置入口

设置 → 房间算法：

| 选项 | 稳定 ID | 实际视觉实现 |
| --- | --- | --- |
| V4-A 差分与门底边（速度优先） | `portal_v4_diff` | 相邻帧差、固定背景差、人体局部门框前景，完全不运行光流 |
| V4-B 局部双向光流（精度候选） | `portal_v4_lk` | A 的背景与安全检查，加门框局部正反向金字塔 LK、空间覆盖检查、有限的出门回看 |
| V4-C OpenCV MOG2（背景分离） | `portal_v4_mog2` | OpenCV 核心模块的高斯混合背景模型，排除阴影标签；以固定背景恢复作保守复核，不运行光流 |

原来的 Legacy、V2、V3 保留。每次只运行选中的一种 V4 后端，不会同时算三遍。参数入口是“V4 A/B/C 参数调整”，每种方案独立保存，也能恢复该方案默认值。

切换算法或修改参数后应从视频开头重播。原来“V3 起始人数”在设置主页面改为“V3/V4 起始人数（可选）”；复用同一份场景/视频初始人数，不另建三套互相矛盾的初值。

## 必须保持的空间语义

只有客厅多边形表示完整标定的主空间。其他门框四边形是图像中的通道/观察窗口及目标房间语义，不是完整房间边界。

本实现不把门框上边解释成“房间深处”，不把单应性变换的纵坐标解释为人的物理深度。未经地面平面标定，头、肩、脚的像素不能混投到同一个“跨门深度”轴后比较。站在门前的人、弯腰的人和已经在门后的人都可能覆盖相似窗口。

门框内部不重叠，使一个像素的窗口归属唯一；但一个人的身体可以同时覆盖两个不同窗口。实现保留候选歧义，不在第一次重叠时永久选门。极少数几何/栅格边界冲突像素中立处理，不让两个门重复计票。

## 共同的进出与人数规则

### 可见跨门：最高等级证据

继续使用可信脚点，或经过历史完整人体校验的地面估计，检查轨迹是否穿过该门的**有限线段**，而不是无限延长线。跨越后要在另一侧持续获得至少两个不同时刻的可靠观测，并满足确认时间；立即退回则取消尚未确认的事件。

厨房、书房等进入后持续可见的情况，不等待人体消失。已经进入子房间的对象继续被 YOLO 检出，不等于重新进入客厅，更不新增人口。退出是同一有限门线的反向跨越。

### 遮挡进入：差分/光流只能补证据，不能替代门槛

对象必须已经被接纳为真人，最近有靠近该有限门底边的可靠地面轨迹，而且最后真实地面观测已经非常接近门槛。

视觉层只在该人的身体与门口有关时收集门内证据。要有可用的空门背景、可靠可见时获得的人体归属、足够空间格子的覆盖、没有其他人争夺，以及该门前景持续消退到接近背景。还要求检测确实覆盖了这个人却持续未检出。

“差分为零”不等于消失；“某个光流点跟丢”也不等于穿门。A/B/C 均不能仅靠这两件事改人数。恢复背景的判断检查整个相应门框内的剩余前景，而不只检查旧像素位置，避免把人在门内平移后留下的空位置当作整个人消失。

极近侧门在最后可靠脚点仍离门很远就被家具/墙挡住时，本版宁可待定。它不会声称单台摄像头能证明所有不可见的运动。

### 出门

三种方案均支持可靠地面点的反向跨越，复用来源房间已存在的匿名人数名额。

B 额外在新人体刚被发现且靠门、没有隐藏客厅对象造成身份冲突时，尝试一次有预算的逆向纹理查询：最多三对历史图像、64 个当前人体纹理点、多个空间格和多个过去时刻一致，才给出来源门提示。提示不是历史脚点测量，也不是生物身份认证。

A/C 没有 B 的逆向光流；如果首次可靠检测已经在客厅，且没有看到跨门过程，仍可能无法唯一识别来源。它们不会把门扇运动或任意门内前景直接当作新的人，也不以“这个房间应该有人”强行补来源。

### 家具遮挡与误检

没有可靠门槛接触的客厅对象丢检，保持客厅遮挡/待定，不自动转入子房间。多人遮挡、ROI 未完整覆盖、推理失败、时间中断均不能作为消失进入的证据。

保留原有 Tracker 的锁定。V4 再要求可信人体结构、多个时刻的地面净位移，以及图像可用时至少两次人体相关局部像素变化。像素变化不是人体分类器，仍必须与原锁定和骨架联合使用。

已接纳的人静止后不删除。但首次出现就一直不动的人可能暂不准入；这与防沙发误检存在真实取舍，不能通过增加无关运动像素解决。可用已知初始人数，或在确认需要时调整准入位移。

### 人数账本

每个已知对象/匿名名额只有一个已提交位置。内部房间迁移守恒，只有入户迁移改变屋内总人数。新检测 ID 不等于新真人，身份接续、重复事件和遮挡待定沿用独立账本。

没有设置初始人数时，显示“隐藏初值未知”，不是宣称未见房间为零。中途开始视频不套用时间零点初值。待定期间整数是最后提交值，须连同候选范围解读。

## 三种后端的实际区别

A：每扇门保留固定背景。无人物、无活动且稳定一段时间后才建立可用于消失判定的参考；有人或事件进行中冻结更新。低成本原生差分、阈值和少量形态学操作生成前景。骨架近似区域只做归属约束，不称为精确人体分割。

B：在 A 上对活跃门框局部裁块运行真正的正反向 LK。默认单门上限 192 点，全局最多两个活跃裁块；单次补点使用一次角点提取再分格限制，不再逐格反复调用角点检测。每个有效源帧只处理一对图像，不补历史积压。全部作为可靠性的光流点都通过反向误差检查，不用“跳过校验”假装加速后仍同等可信。

C：使用现有 OpenCV 4.13.0 的 `video.BackgroundSubtractorMOG2`，无需 contrib 或新神经网络。彩色局部输入保留 MOG2 阴影识别，输出 127 的阴影不计入人体前景，255 才算前景。有人/事件时学习率为零。固定背景差仍作消失的保守兜底，因此 C 不是仅凭 MOG2 一张掩码判穿门。

## 调度与性能

本版采用**单个已准入图像任务，零待算图像队列**。V4 回放先取得处理名额，再做 TextureView 读回；忙时不截图、不灰度化、不入队。空闲后处理下一张当前画面，而不是历史画面。

YOLO、身份关联、V4 视觉和房间状态仍按同一源帧串行处理。这样不产生迟到 Pose 被高频状态机抛弃的问题。鉴于当前 Pose 约 50ms，先移除积压和全身光流，比引入复杂多时钟并发更容易保证正确。

灰度缩小、颜色转换和差分在工作线程，主线程只进行已准入的 Bitmap 读回。读回本身仍可能阻塞 UI，不能说已经完全消除 UI 成本。回放采样图长边可调：A/C 默认 1280，B 默认 1920；它会影响小 ROI/手部的源像素密度，测试小手势时应设 2560（当前约 2232 宽视频即可保留原尺寸），或切回旧链路。

V4 不启用 V3 的 32 帧灰度缓存。B 的最多四张灰度历史仅供少数逆向查询，是只读缓存，不是前向工作队列。光流预算限制是否启动下一项可选工作，不能强制中断已运行的 OpenCV 原生调用。

50ms 采样周期表示理论上最多 20 次/秒，不保证实际 20 次。如果 Pose 本身 50ms，加读回和后处理，串行输出会低于 20fps。最终是否达到 10fps 下限，必须看目标手机实际测量。

## 画面与日志怎么读

“输出 fps”按墙上时间统计已处理的独立证据帧，不是播放器渲染 fps，也不是视频时间被快进后的虚假频率。
`Pose` 为现有分析器报出的检测及关联耗时；`视觉` 是整轮 V4 视觉而非单对内部 LK；`总链` 是采样至处理结束的上一轮耗时；`读回` 单列。
`队列=0` 表示没有待算图像队列，不表示没有一个正在处理的任务。跳过次数是被背压/周期限制拒绝的采样尝试，不冒充真实解码丢帧数。

黄色格子是门内前景覆盖，不是精确人体分割。B 的绿色线才是真正测得的局部光流。没有绿色线不代表一定没有人；应同时看门前景、背景预热、脚点与状态原因。

## 源码对应及官方依据

主要实现位于 `logic/roomalgorithm/gate/`。共同账本复用 `PortalV3Core`，新增可选策略参数；旧算法使用默认策略，其回归行为必须保持。

- Android TextureView 尺寸读回 API：https://developer.android.com/reference/android/view/TextureView#getBitmap(int,int)
- OpenCV MOG2、学习率和阴影：https://docs.opencv.org/4.13.0/javadoc/org/opencv/video/BackgroundSubtractorMOG2.html
- OpenCV LK 与角点示例：https://docs.opencv.org/4.13.0/d4/dee/tutorial_optical_flow.html

这些资料证明所用 API 和算法语义，不证明本机帧率或房间识别准确率。三个方案的可用性以构建结果、合成回归和真实视频三类证据分别说明。
