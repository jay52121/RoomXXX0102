# V5.1 实时差分穿门：事件发生与输出时刻

## 定义与对照版本

- 算法 ID：`portal_v5_1_diff`；设置列表名：**V5.1 · 实时差分穿门（验证版）**。
- 旧 V5.0：`portal_v5_diff` 保留，不修改它的工作逻辑。
- 新 V5.1：独立 `DiffV51Core`，视觉测量仍复用现有 Event ROI、OpenCV 前景差分与调度器，**未实现完全独立的无脚点激活层**。判定层不调用 V4 脚点穿线或 V5.0 离线整段分类。
- V5.1 核心的事件 `timeMs` 只使用**真正输出该事件的分析帧时刻**，不会把过去的检测帧或人工标注时间伪装成输出时刻。

## 两套验收指标

对人工标注穿门时刻 T：

1. 正确房门、正确进出方向，算法实际发表事件的**视频帧时刻**不早于 T−100 ms 且不晚于 T+1000 ms：一对一严格命中。
2. 响应速度的目标是 T+500 ms 内，逐条统计；这不是已经实现的硬保证。
3. 绝对禁止将历史穿门时刻回填成响应时刻；程序当前实测的真实**墙上钟表延迟**还取决于设备视频播放、采样、队列和图像处理。回放单测所报延迟是事件输出所在帧**视频时间**与人工标注视频时间之差。

## 实时状态机

- 每帧接收门口像素归属、伪深度、人体门区侧向位置、门内覆盖率与 motion；不读取人工真值。
- 在门区活跃期检测近实时「向门内运动」「离开门区」「朝门外运动」「持续吸收后遮挡」「出入反向」的直接证据；按因果确认时间（0–180ms）后发布，而不是等整段门区活动结束。
- 提交证据与人数发布分离：候选保留短期预约和防重，只有实际发出事件时更新公开人数。
- 同一门区发生一次简短 Track 号交接时可拼接连续差分证据；不支持追踪 ID 反复交错/多人同时穿门时强行合并。
- 用真实毫秒，而不是固定帧数做延迟确认、丢检 HOLD、持续运动确认。
- 本版仍可能对新的视频场景误报或漏报；应保留 V4、V5.0 可选并可回退。

## 两次实际采样回放的成绩

| 输入 | 分析帧数 | 有效门区差分记录 | 人工标注 | 按实际响应视频帧严格匹配 | 未匹配输出 | 500ms 内命中 |
|---|---:|---:|---:|---:|---:|---:|
| 原 V4 导出的差分证据 | 1431 | 837 | 32 | **32/32** | **0** | **21/32** |
| V5.0 真机导出的差分证据 | 1786 | 1080 | 32 | **32/32** | **0** | **19/32** |

**重要：两份导出来自同一段原视频，而非两部独立新视频；此成绩是开发录像回归，不是跨场景准确率保证。**

两次回放的测试资源分别为：
- `app/src/test/resources/v51_old_diff_replay.txt`
- `app/src/test/resources/v51_native_diff_replay.txt`

单测：`DiffV51CoreTest`。两份资源的 `T|` 行只由测试用来**打分**；实际分类器只接收 `S|` 行转换的门区差分值和 `F|` 行帧时间/健康状态，绝不把标注时间或答案作为输入。

## 上机后如何测

1. 正常从工作分支编译并安装应用，不需要下载独立实验包。在设置中切换到 **V5.1 · 实时差分穿门（验证版）**，与旧 V5.0 使用相同几何、初始人数、采集参数。
2. 开始完整播放/录制，导出**全程正式算法判定输入与输出**；保留每帧输入时刻与发表事件所在帧时刻。
3. 用人工 32 条门、方向和不对称窗口 `[-100,+1000]ms` 做一对一匹配，单列 `[−100,+500]ms` 达标数、平均/最坏响应延迟、额外输出、人数状态。
4. 接下来必须对**未参与开发的新录像**和站门口、反向折返、多人互相遮挡、摄像头掉帧/卡顿开展测试；重点盯最大1000ms边界是否会被新场景突破。
