# Portal V4：三个方法都不行时怎么办

## 先判断是共同输入错误，还是视觉方法不适合

A/B/C 共用 YOLO、人体准入、门底边几何、状态机和人数账本。三版都错不自动证明“差分和光流都无用”，很可能是共同依赖有问题。反过来，三版都通过编译，也不证明实际遮挡可解决。

| 失败现象 | 优先检查 | 不应先做 |
| --- | --- | --- |
| 三版都选错同一扇门 | 门底边关联 ID、归一化坐标、宽高比、旋转/裁剪、ROI 坐标映射 | 再加一个更大网络 |
| 有可靠脚点跨门却不出事件 | 人体是否准入、是否穿有限段、连续确认、是否在共用端点、是否有冲突状态 | 一律降低所有阈值 |
| 家具遮挡后误进房 | 最后真实脚点距门、门前路过轨迹、窗口前景归属、遮挡区域是否投影到门内 | “门框不重叠所以不会错” |
| 人在门里停住被判消失 | 固定背景状态、门扇/曝光、残余前景，不能只看帧差 | 把光流失败当死亡证据 |
| 进入后持续可见被反复计数 | 提交房间与可见检测是否混淆、事件去重、ID 接续 | 单看当前框落在哪个窗口 |
| 出来时第一帧已经在客厅 | 原始采样时序、是否能观察真实门槛、B 的逆向来源是否有覆盖 | 从“刚出现”推断它来自最近的门 |
| 单门两人并排/相互遮挡 | 同时人数、实例分离、归属冲突 | 用一团前景面积除以标准人面积 |
| 总人数越来越大 | 初始名额、新 ID/真人是否混淆、ROI 掉检、重复事件 | 继续优化前景颜色 |
| A 也很慢 | 读回尺寸、主线程、手势同时推理、YOLO 真实耗时、UI 绘制与日志 | 调高采样频率制造更多压力 |
| 只有 B 慢 | 光流工作图、有效门数、点数、可选预算与逆向查询 | 重新补算所有历史帧 |

## 下一步 1：先修输入、采集与几何

把同一源帧的原图、门底边、可信脚点、检测 ROI 和时间戳叠在一起检查。门框可以正确，但底边 ID 解析错误；人体框可以正确，但脚点是截断框底或裁剪 ROI 边界。新算法不能补救这种基础错位。

如果采样仍然是瓶颈，下一步是把解码/相机的小尺寸分析图直接交给工作线程，避免 TextureView 大图读回；需要保留旋转、宽高比和 ROI 一致性。只有量化采集、Pose、视觉、UI 各自成本后，才决定是否建立独立的低分辨率门口通道。不能简单并行多个状态机，也不能丢掉迟到的唯一身份锚点。

## 下一步 2：确实卡在“哪些像素是这个人”，再考虑人体分割

门扇、影子、家具、多人重叠，可能让 Pose 近似人体区域不足。此时有针对性的升级是**只在门口事件期间运行轻量人体实例分割**，而不是全帧长期运行大型视频模型。

必须实测：
- Android 实际模型文件、输入输出、支持算子、GPU 与回退；
- 小半身和只剩头肩时的召回；
- 增加的单轮延迟、常驻内存和发热；
- 它是否真的修复了前景所有权，而不只是画得更好看。

不能凭“分割模型更先进”承诺高准确率；人物完全不可见时它也不能看穿墙。

## 下一步 3：缺少门口观察语义时，收集少量明确示例

对难门记录几次明确进入、退出、路过、停住和退回，标签必须由人确认，不把当前算法结果当训练真值。

可学习的是该机位下的图像运动/遮挡统计，不是凭几个四边形还原三维深度。不同走速、衣服、身高会改变统计，少量例子只能形成弱先验，不能承诺“3 次必然学会”。

必要时给个别门补一条明确的遮挡边界或一个“门后才能出现”的见证区，但要先证明该区域在图像上不会被客厅人物投影覆盖。不是要求重新画完整户型。

本次三版不自动自我训练，也不把待定或推断事件写成高置信学习样本；避免实验顺序污染结果。

## 下一步 4：无法区分的视角，需要改变观测

两个真实过程可能在单个固定机位产生近似相同图像：
- 人在门前被沙发挡住，与真正入门；
- 人从邻门出来但第一次被看见已在相同位置；
- 两人在门后交换身份；
- 房间里一开始就有人且从未出现在客厅。

遇到这类无法由当前证据区分的情况，合理的产品选择是保持待定、调整机位、补充门磁/人体传感器或另一观察视角。门磁只能证明门开关，不等于通过人数；要与视觉融合。

不能把“输出一个确定数字”当作比“显示不知道”更成功。未观测的初始房间人口也不可能由客厅像素唯一推出来。

## 验收边界

新方案首先应避免将原本可靠的地面跨门与人数守恒破坏，并解决 V3 无界补算/远离门运行光流的问题。真实的近侧遮挡、多人同门、阴影、玻璃和极低对比图像仍要在目标视频上验证。

三个方法都失败后，不自动添加第四套相似阈值规则。先根据上表确定共同故障点，再决定改采集、修几何、升级分割、增加明确样例，还是承认可观测性不足。
