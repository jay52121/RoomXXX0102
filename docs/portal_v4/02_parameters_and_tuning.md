# Portal V4.1：Event ROI 参数与调试顺序

## 先看状态，不要先调阈值

设置 → 房间算法选择 V4-A/B/C，再进入“V4 A/B/C 参数调整”。三个方案独立保存。修改后从同一视频开头重播，并保持相同的初始人数。

V4.1 的调试顺序应是：

`候选人体 → ARMED → ACTIVE → HOLD/可见跨门 → 视觉证据 → 人数提交`

如果面板始终显示 `活跃门 0`，先检查候选/门几何；不要去调差分阈值。如果已经 `ACTIVE` 但黄色真实轮廓不对，再调视觉参数。

## 共用参数

| 参数 | 默认 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| 采样周期 ms | 50 | 33–200 | 主 Pose/房间链理论最高频率；忙时直接背压，不排队 |
| 源截图长边 | 2560 | 960–2560 | 当前约 2232 宽测试视频默认不缩小；门 ROI 直接从此图裁出 |
| 连续视觉最大间隔 ms | 300 | 150–500 | 超过即重置事件连续性，防止跨长间隔推断 |
| 局部亮度差阈值 | 18 | 8–60 | 越低越敏感；噪声/曝光变化多则提高 |
| 门历史长度 ms | 1000 | 600–1600 | 所有门“只存不算”的 pre-roll 时间，用于约 0.5 秒后锁定的人体回溯 |
| 掉检后 HOLD ms | 900 | 400–1600 | 门口人体消失后继续观察该门多久 |
| 候选启动最低分 | 0.25 | 0.10–0.80 | 只决定是否允许门传感器提前准备；不能直接改人数 |
| 候选靠门距离 | 0.28×人高 | 0.12–0.50 | 越大越容易提前 ARMED，也更容易唤醒相邻门 |
| 门裁块 padding | 0.015 | 0–0.08 | 在标定门四边形外额外保留少量源图像素 |
| 同时运行视觉的门上限 | 2 | 1–3 | ACTIVE/HOLD 真正执行差分/MOG2/LK 的门数硬上限 |
| 调试轮廓最小面积 | 6 px | 2–80 | 只控制小噪点轮廓显示/统计过滤，不代表差分块大小 |
| 背景恢复确认 ms | 200 | 120–1000 | 前景下降后必须稳定多久才算窗口恢复 |
| 允许残余前景比例 | 0.08 | 0.02–0.20 | 越大越容易确认清空；过大会提高误报风险 |
| 门槛接触带 | 0.10×人高 | 0.05–0.20 | 影响进入 ACTIVE 及遮挡补证据的近门条件 |
| 可见跨门确认 ms | 120 | 100–600 | 有可靠脚点跨门后需要的独立时间确认 |
| 真人准入最小位移 | 0.012 | 0.005–0.04 | 防静态误检；不是米数 |
| 遮挡证据最长保留 ms | 1400 | 600–2500 | 旧门口证据过期时间 |

`visionEdge=480/640` 已不参与 V4.1 Event ROI 计算，只为旧配置兼容保留，因此设置页不再暴露它。

未激活门的 pre-roll 默认以约 10fps 保存，不执行差分/MOG2/LK；ACTIVE/HOLD 门才跟随主采样频率处理。

## A：纯局部差分

先观察黄色半透明**真实前景轮廓**：

- 人体经过门却几乎没有轮廓：适度降低 `亮度差阈值`，同时确认源截图仍为 2560、门标定位置正确。
- 门框纹理/压缩噪声到处闪：提高亮度差阈值，必要时提高轮廓最小面积，但不要先放宽房间提交条件。
- 人还在门里，却很快认为窗口清空：降低“允许残余前景比例”或增加“背景恢复确认 ms”。
- 人确实进去但一直待定：先确认是否真正 `ACTIVE/HOLD`、最后可靠脚点是否接近门槛，再看背景是否因为门扇/其他物体始终无法恢复。

A 的帧差只用于人体变化/ownership 辅助；静止人体不会因为“相邻帧差=0”就被认定为消失，因为清空依据仍看事件开始前的局部参考背景。

## B：局部双向 LK

| 参数 | 默认 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| 单个活跃门特征点上限 | 128 | 48–256 | 只在 ACTIVE/HOLD 门局部高分辨率裁块中存在 |
| 正反向误差容限 | 1.5 px | 0.5–3.0 | 越小越严格；单位为门 ROI 源像素 |
| 金字塔最大层号 | 2 | 1–3 | 大位移需要更高层，但成本增加 |
| 可选光流/回溯预算 | 30 ms | 10–80 | 超预算不再启动后续可选工作，不产生积压 |

新的 LK 窗口为 `15×15`、较少迭代，并且只在高分辨率局部门裁块上建立金字塔。内部空间覆盖使用更细的 `8×12` 统计，不再把 4×8 大块画在屏幕上。

调参顺序：

1. 先看门 ROI 是否清晰、候选是否进入 ACTIVE；
2. 再看绿色点是否分布在多个人体部位；
3. 特征不足时再提高点数/金字塔；
4. 如果 `视觉 ms` 明显上升，优先把点数降到 96/64，不允许用积压换精度。

晚出门回溯只分析当前唯一候选门最近的 pre-roll，并要求多个纹理点在多个历史帧上方向一致；光流跟丢本身永远不是进门票。

## C：MOG2

| 参数 | 默认 | 范围 | 作用 |
| --- | ---: | ---: | --- |
| MOG2 方差阈值 | 16 | 8–64 | 越低越容易判前景 |
| pre-roll 预热学习率 | 0.025 | 0.002–0.08 | 事件开始时只用该门历史预热；事件期间学习率为 0 |

C 不再让 7 个 MOG2 模型 20fps 常驻 `apply()`。只有 ACTIVE/HOLD 门才创建/使用模型；历史图仅在事件开始时用于快速预热。固定参考差分继续作为清空安全复核。

## 候选门太多/太少怎么调

### 总是活跃 0 门

检查：

1. YOLO/Tracker 是否确实输出了未确认候选；
2. 门底边与人体坐标是否在同一归一化坐标系；
3. `候选启动最低分` 是否过高；
4. `候选靠门距离` 是否过小；
5. 下半身/脚点是否被严重截断。

### 人离门很远也经常 ARMED

先减小 `候选靠门距离`，而不是提高差分阈值。ARMED 本身不运行高成本视觉，但过宽会影响门候选解释。

### 经常同时两扇门

相邻门场景允许短时间 2 门候选，这是设计行为。最终视觉提交仍要求有限门线/独占证据。如果实际几何上不应出现，可减小候选距离或裁块 padding；不要直接强制“最近门必胜”。

## 调试面板

重点看：

- `输出 fps`：实际完成的 Pose/房间证据帧率；
- `Pose ms`：现有 YOLO/Tracker 耗时；
- `视觉 ms`：当前 Event ROI 后端整轮耗时；
- `活跃门`：真正执行差分/MOG2/LK 的门数，正常大多数时间应为 0，过门时通常 1，极少数相邻/多人场景为 2；
- `门历史 KB`：约 1 秒 pre-roll 的实际缓存大小；
- `光流点`：B 版当前局部门有效点数；
- `队列 0`：没有待算图像任务；
- 黄色轮廓：真实前景 mask，而非显示放大的网格。

## 仍不允许放开的安全条件

1. 未正式接纳的人体不能只凭门口像素运动增加人口。
2. 门线始终是有限线段。
3. YOLO 消失、帧差归零、LK 点丢失都不是独立穿门证据。
4. 推理失败、ROI 未覆盖、时间跳跃不能伪装成人体消失。
5. 家具遮挡但未发生门接触时，客厅位置保持不变/待定。
6. 内部房间迁移必须守恒全屋人数。

每次只修改一个参数，并用同一错误片段和至少一个原本正确的“路过门口/家具遮挡”片段一起复跑，防止只提高召回却破坏误报率。
