# V5 独立差分：Android 实测入口与验证边界

## 当前状态
- 算法 ID：`portal_v5_diff`；选择界面名称：**V5 · 独立差分穿门（实测版）**。
- V4-A/B/C 保持原样，不切换默认算法；V5 只能通过手动选择启用。
- **判定层完全独立**：`DiffV5Core` 从未使用 `PortalV4Core`、`GROUND_CROSSING`、脚点穿线或 `WAIT_CLEAR`。
- **采集层仍复用旧 Event ROI**：`GateActivityScheduler` 使用已有门附近的人体接触来启用局部 OpenCV 差分。因此整个管线目前仍会受到已有下半身/脚点采集逻辑的影响；不能宣称 V5 已完全摆脱脚点依赖。
- V5 必须得到 OpenCV 局部差分证据才能作出事件，视觉不可用时**不回退** V4 脚点算法。

## 实测方法（使用原视频，而不是仅测试构造的条件）
1. 在同一机位、相同房间与门几何、相同初始人数设置下，从视频开头分别运行 V4-A 和 V5。
2. V5 的设置项独立保存；首次建议保持原始采集参数不变，便于对照。
3. 开启事件诊断录制，关注 `GateV5.0-DIFF-ONLINE-EXPERIMENT`，门区 ACTIVE/HOLD、局部差分归属像素、深度分布与 V5 事件。
4. 对同一份人工绑定门真值做一对一、方向+门、±1000 ms 配对；同时报告**额外输出数**、漏报、延迟及全程人数账本。
5. 额外验证慢走、站门口、退回、家具遮挡、单门多人、间歇掉检、视频跳转与无 OpenCV；不要只测试那 32 个开发事件。
6. Android 中 V5 事件采用**回填原始运动帧时间**，但实际向 UI/日志提交需待该门约 700 ms 的无活动间隔。历史片段中通常有秒级延迟，长时间持续占门会更长，不能把回填的时间误当作实时响应延迟。

## 可复现的判定层回放
- 输入：`app/src/test/resources/v5_diff_replay.txt`；从 1431 个真实分析帧提取 837 个实际门区证据。
- 原生 Kotlin 单元测试：`DiffV5CoreTest.recorded1431FramesMeet32HumanDoorTruthsWithoutExtraEvents`。
- 基线：32/32 配对、0 多余输出。此结果只证明**已保存的门区证据**能够被 V5 Kotlin 在线状态机判对。
- 标注行仅被测试读取用于打分，`DiffV5Core` 永远只收到 `DiffV5Signal`；禁止 GT 时间戳、门号或事件结果反灌判定。
- 同时包含静止负样本、推理失效时不作虚假决策、身份源切换保留人数的单测。
- 编译命令：`./gradlew :app:testDebugUnitTest :app:assembleDebug --no-daemon`。

## 尚不能声称的事
**未能在本端操作用户的实际 Android 设备。** Kotlin 实例级测试、GitHub Actions Android 构建与真机播放是不同层级的验证。应用编译成功也不能替代视频上的实测。原型对丢帧敏感：随机丢弃 3% 帧，仅 10/20 轮保持整段全对。V5 当前仍为可选实验算法，PR 应保持草稿，禁止直接作为默认模式合并上线。
