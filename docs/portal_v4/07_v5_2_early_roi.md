# V5.2：差分门区提前采集 + 短遮挡因果判定

## 范围

- 算法 ID：`portal_v5_2_diff`。与 `portal_v5_1_diff` / V5.0 / V4 并列提供；不更改旧算法，默认项不变。
- **采集侧**：`GateActivityScheduler` 仅在 V5.2 中根据人体**整框和门区投影矩形交集比例**（至少 24% 候选，36% 接触）提前启动局部像素分析；连续两个分析时刻（至少 60ms）才进入 ACTIVE。单次最多计算两扇门，ID 切换重新确认，不使用脚点进入 ACTIVE。其他版本仍按原下半身门槛规则。
- **判定侧**：复制 V5.1 为独立 `DiffV52Core`，保留原先的全部判据；新增短时间 ACTIVE（3～5 帧）之后在 HOLD 的持续视觉运动推断。近门稳定遮挡和远侧移动后人体真正消失使用不同判据，**HOLD 时仍有可见人体离开门区不能认成进入**。
- 对短期消失且可见阶段不足 650ms 的旧 `absorbed-disappearance` 判据等待至少 130ms 确认，避免过早 100ms 以上提交。
- 修复漏判连锁：只有 `moving-outside` 且方向运动量、前景覆盖减少及可信度同时很强时，才允许 EXIT 绕过旧账本中人数=0的限制；不补造一个不存在的 ENTER。
- 完成后响应帧的真实视频时间写入事件，不回填旧帧。V5.2 不读取人工标注参与判定。

## 已保存差分证据的三套因果回放

| 数据来源 | 分析帧 / 有效门区记录 | 严格命中 | 不匹配输出 | <=500ms |
|---|---:|---:|---:|---:|
| 原始 V4 录制 | 1431 / 837 | **32/32** | **0** | **21/32** |
| V5.0 Android 录制 | 1786 / 1080 | **32/32** | **0** | **19/32** |
| V5.1 Android 最新录制 | 1633 / 981 | **32/32** | **0** | **21/32** |

严格匹配方法：每个人工标注和实际发出事件**按门、方向、一对一**匹配，时间差必须在 **−100ms～+1000ms**，其中 **+500ms** 单独报告。人工 T 行只用于测试计分，测试 `DiffV52CoreTest` 将 F/S 时间和实际差分输入逐帧注入核心，不用 GT 或旧正式输出辅助判断。

三套数据实际上来自**同一部原始视频的不同采样/算法阶段**，所以这是开发录像的回归成绩，**不是独立新视频的泛化证据**。

## 仍未验证的部分

- 原始 JSON **没有原视频画面像素**，所以只能证明判定核心如何处理已经保存的差分测量；V5.2 的新提前激活会改变什么时候采集、背景参考帧、差分像素值和计算负荷。**上述 32/32 不代表开启 V5.2 提前采集之后的真实 Android 视频结果**。
- 由于身体框会在门附近停留，提前采集可能造成新的误触发或背景参考污染；务必真实录制同一段视频，并测试人物徘徊、家具遮挡、多人同时接近相邻门、Track ID 切换、零有效像素、抽帧。
- 本算法仍用人体 bbox 作为局部像素采集的触发条件；它摆脱的是**依赖脚点接触才能启动**，并不意味着纯视觉差分已经独立完成目标跟踪。采集并发仍受 `maxActiveGates` 约束。

## 实测与回退

安装从工作分支编译的正常应用，在房间算法下拉中选择“V5.2 · 提前采集实时差分（验证版）”并从视频头部开始播放。导出**全程正式算法判定**，以每帧 `outputs` 出现的 `frame.timeMs` 作为响应时间，不允许读取可能回填的事件时间代替它。记录 32 条个别偏差、漏报、误报、全程人数状态和 ACTIVE/ARMED 时间轴。

如果新采集造成性能或精度回退，可以直接切回 V5.1（代码仍保留），或回退本 PR 的合并提交。
