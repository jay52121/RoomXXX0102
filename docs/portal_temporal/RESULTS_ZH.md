# V6 上身时序模型：代码与实测结果
日期：2026-10-13

## 已经做成的部分
不是下一轮架构计划，而是已经训练、导出、编译并逐帧运行的检测器。输入是现有六份真实录制中的人体检测/上身关节点和门区几何，输出是进入/退出事件；不要求补视频才开始工作。

算法是**已知机位的监督式时序分类器**，不是声称从二维画面恢复了真实三维门平面。它从训练标注学习事件对应的上身姿态和短期运动规律；原32个标注只在离线训练和最后评分使用。运行时不读取标注、绝对视频时间、事件序号、房门ID或以前算法输出作为特征。房门和Track ID仅用于输出路由、分组和身份隔离。

## 比已知回放更严格的验证
**最终版本的逐录制留出**：每次只用其他五份训练；六轮严格正确合计 **191/192**。五轮32/32，一轮31/32（漏掉第12条）。早期中间版本曾报告六轮全对，最终冻结后的结果以本节为准，不沿用中间结果。

这仍然不属于独立动作盲测，因为同一个真实动作在另外五份采样中出现过。

**整组动作留出**：把最前10次动作从六份训练数据中全部排除，仅用后面的动作训练。对六份留出采样，各只识别8/10，并有1～2次额外输出。结论：**未知动作泛化验收未通过**，不能把本模型宣称为可靠的通用房门检测器。

## 固定模型扰动测试
每种条件30组，覆盖六份原始录制、每份五个固定随机种子；相同训练模型不重新拟合。
| 条件 | 32条全部正确且零额外输出 | 最少严格正确 | 最多额外输出 |
|---|---:|---:|---:|
| 随机删3%分析帧 | 30/30 | 32/32 | 0 |
| 随机删10%分析帧 | 27/30 | 31/32 | 1 |
| 关节点独立0.5像素标准差抖动 | 29/30 | 31/32 | 1 |

3%删帧条件全部满足1秒硬时限，但不是每次所有事件均在500ms内；最差有1条超过500ms。不能将此表写成“所有扰动均满足全部指标”。
原生契约测试 **8/8通过**：六份严格全量回放、时间原点平移、Track编号整体变换、门名/门遍历顺序变换、门名/门遍历顺序变换、32个冷启动静止姿态负例、空输入/失败推理、前缀因果性、人数账本与损坏模型拒绝。8个测试函数合并了若干子项。执行的是原生Kotlin逻辑配合兼容断言驱动，不是Android Gradle整项目构建。

## 实现与代价
- 69个特征：固定左右肩/髋相对门区位置和体态比例；0/120/280/500/850/1250ms因果历史；前后同名上身点的位移统计与支持数；门区几何比例。
- 350棵深度5的树；模型文件约195KiB。Android运行不依赖Python或CatBoost库，只有纯Kotlin树推断和gzip读取。
- 不使用脚、膝、框底部穿线。人体框仅做候选门选取/点合法性检查；不扫描所有门的高帧率图像、不再强制依赖每门光流。
- 必须看到同名点的真实运动才能触发；速度按实际dt归一化，避免采样变密时每帧位移被固定阈值抹掉。
- 当前每门每方向1800ms去重。紧密多人连续穿同门未验收，不能宣称支持；未知房间初始人数也不能仅靠事件回放证明绝对人数准确。
- 训练窗口 [T+80,T+650]ms，预测时不读T。场景相关参数与已知样本标注参与训练，需要独立动作评估；不能把“标注不是输入特征”误写成“没有使用标注训练”。

## 工程交付状态
GitHub 工作分支中的 V6 作为**独立实验选项**接入，不改变旧版算法和默认选项。仓库包含模型资产、纯 Kotlin 运行核心、Android 适配、JUnit 源码、六份带源哈希的回放夹具、训练/验证脚本及结果报告。

打包时的独立 Kotlin 回放与契约测试已执行；接入 Android 工程后，必须以对应 GitHub PR 的 Gradle CI 状态判断是否完成 Android 单元测试和 Debug 构建。**未经手机从原始视频全流程重新运行及独立新动作验收，不得称为生产就绪。**

原始压缩包中附带的 `apply_to_repo.py` 仅供离线仓库接入使用；在 GitHub 工作分支中已经集成后不需要再执行该脚本，以免重复修改。

## 不可偷换的结论
**已知六份记录的32/32与500ms目标，本次确实由新检测代码达到；完整可靠性验收仍未通过。** 未通过项包括独立动作泛化、部分扰动以及Android完整流水线实测。以上失败与通过一起交付，不减小原32条要求、不把工程通过当产品通过。
