## 原因与策略

原状态机每次成功转移后进入 `WAIT_CLEAR`；只要旧门深度或脚点/下半身持续靠近门槛，状态锁保持，**不会评估同门的真实反向穿越**。这使卫生间退出被拦截，并污染后续房间账本。

此次小范围修复仅允许以下情况下在 `WAIT_CLEAR` 直接提交反向转移：

1. 上一次提交之后重新累计的强脚点，在新来源侧至少 3 帧、跨度至少 250ms，最新侧证据不超过 800ms；
2. 当前分析帧仍存在新鲜强脚点，且真实从来源侧穿过有限门线到对侧；
3. 满足去抖等待时间和门距限制，不用单帧重叠替代穿越；
4. 其余 `WAIT_CLEAR` 清理规则原样保留。

新增 Kotlin 单元测试：长期深度占据门区但可靠反向穿越能退出；只有单次短暂抖动时不能退出。未修改采集、YOLO、ByteTrack、其他 V4 状态机判据。
