# SISP 结构化网页调试台 V1

## 使用

1. 在 Android SISP 中打开 **回顾模式**、选择「看人视图」，点击右侧 **网页调试**。
2. 手机、电脑连接同一可信任局域网；在电脑浏览器输入手机弹窗中的完整网址（含一次性配对码）。
3. 不需要额外电脑应用。服务在手机上手动启动，退出应用或点击「停止服务」即关闭。

**强约束：不传原视频、截图、Bitmap、音频或逐像素 Mask。** 页面使用空白的摄像头归一化画布，由 JSON 绘制已有房间边界、门口、17 个 Pose 点、人体框、Track ID、人数与房间判定证据。手机原有视频仍在手机上播放。

## 操作

| 网页 | 行为 |
|---|---|
| 空格 | 播放/暂停 |
| ← / → | 后退 / 前进 **5 秒**，不因暂停状态改成逐帧 |
| , / . | 后退 / 前进 **1 帧** |
| 进度条 | 根据手机视频的真实时间轴 seek |
| I / O | 在当前视频时间标记 **进入 / 离开** |
| 人工事件表、蓝色时间线刻度 | 选中事件并跳到对应时刻 |
| 房间标签、多边形、房间列表 | 将选中事件绑定对应子房间，可重复点击改绑 |
| 下一未绑 / 解绑 / 切换进出 / 删除 | 对已选中的单个人工事件执行操作，实时持久化到原 EventMarkerManager |
| 「无正确匹配 → 返回人工事件并暂停」 | **默认关闭**。人工事件的 ±1000ms 匹配窗口已经被完整观察、且状态不是 MATCH 时才会一次性跳回，包含 MISS/WRONG_PORTAL/WRONG_DIRECTION；PENDING/UNOBSERVED 均不触发回跳 |

自动回跳启用期间临时跳过手机旧有的“房间切换自动暂停”，防止两种暂停策略互相打架；关闭网页自动回跳即恢复手机原有自动暂停设置。V4 本身不作改动。

右侧展示两条事件序列：人工 ENTER/EXIT 与算法输出。标记与算法按时间、方向、人工绑定房门进行**一对一**匹配，明确区分 MATCH、MISS、WRONG_PORTAL、WRONG_DIRECTION、PENDING、UNOBSERVED（窗口没被完整分析不能算漏判）。未绑定房门时 MATCH 只表示**进出方向匹配**，不能作为门级真值。

## 架构与消息

入口：`MainActivity.showWebDebugDialog`；本地服务：`SispWebDebugServer`；网页资源：`app/src/main/assets/sisp_debug.html`。

服务只响应 `GET /?code=<PIN>` 和 `WebSocket /ws?code=<PIN>`，端口 8765；限制本机/私有网段、随机配对码、最多 2 个会话，传输使用原生 Java Socket（无服务端依赖）。**HTTP/WS 为明文协议，只能在可信局域网内使用，禁止公网端口映射。**

发送 JSON：
- `type=frame`：视频时间戳、frameSeq、图像尺寸（**不含像素**）、Pose 人体框/17 关键点/置信度、Track 信息、各 Track 的房间进出候选、reject reason、pending door、调试摘要。
- `type=state`：视频进度/播放状态、算法版本、房门/房间几何、当前人数、人工事件和绑定、算法事件、匹配分类、当前选择、自动跳回开关。
- `type=response`：无效操作返回说明。

网页 `cmd` 只允许固定白名单：`sync`, `play_pause`, `seek`, `seek_delta`, `step`, `select`, `navigate`, `next_unbound`, `mark`, `bind`, `unbind`, `flip_type`, `delete_selected`, `auto_bounce`。全部交由主线程调用当前 Android 播放器/标记器，网络线程不直接修改真值。

## 限制

- 纯结构化画布不能核对原视频像素，因此 **Pose 原始检测是否准确，仍需要用手机原视频验证**。
- 打开网页服务以前的 Pose 帧不可能凭空重建；可从视频开头回顾一遍，网页会缓存接收的结构化帧。跳过未分析区间不当成算法漏判。
- 本版对 **回顾视频** 提供远程编辑；实时模式可观察部分状态，但不支持直接标注。
- 不使用远端推理，不上传数据到云端；保存的人工标注仍在本机，网页可把本次接收到的结构化帧/标注导出 JSON。
